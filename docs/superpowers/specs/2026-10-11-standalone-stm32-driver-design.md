# STM32 两文件接入方案

## 目标与适用工程

分别为 STM32F103C8T6、STM32H723VGT6 提供 remote_control.c 和 remote_control.h。把对应型号的文件加入现有 HAL 工程，包含头文件，在 HAL_Init() 和 SystemClock_Config() 后调用 RC_Init()，即可启动接收与断连保护。无需生成或加入 uart.c、tim.c，无需修改 stm32xx_it.c，也不需要开启 HAL 的 UART/TIM 模块。

工程仍需提供芯片 CMSIS、基础 HAL/RCC、启动文件、链接脚本及系统时钟。这里不替代完整芯片工程。两种型号的文件不能同时加入同一个工程。

## 方案选择

采用寄存器初始化加 RAM 中断向量表：驱动自行配置外设，通过私有静态中断函数接收数据和计时，初始化时自动安装两个入口。

另外两种方式不采用：导出弱同名中断函数会被原工程的强中断函数覆盖，不能保证接收；要求原工程在中断中转发或在主循环轮询，会增加接入步骤，不能满足一行初始化。

## 接口与外设

- 保留 g_rc 全局结构体、RC_GetState()、既有协议和 300 ms 断连归零逻辑。
- RC_Init() 默认 9600 baud；RC_InitBT630() 默认 115200 baud；RC_InitBaud(baud) 支持指定波特率。
- 默认 USART1：PA9/TX、PA10/RX，8N1。TIM4 提供约 1 ms 定时中断。
- 根据当前外设时钟计算串口分频和 TIM4 周期，不改变系统时钟、共享时钟源或全局中断优先级分组。
- 直接初始化所需 GPIO 和外设寄存器，不调用 HAL_UART_Init()、HAL_TIM_Base_Init() 或生成的 MSP 回调。

## 占用与失败行为

用户已选择：原工程启用 USART1 或 TIM4 时返回 HAL_BUSY，保留原功能。

首次初始化采用保守检测：任一目标外设的 RCC 时钟门已开启，或任一目标中断已启用，均视为占用。检查和安装在短暂关闭中断的临界区内完成；恢复调用前的中断屏蔽状态。所有参数和时钟检查先于硬件及 g_rc 修改。F103 还需检查 USART1 的保留重映射：临时启用 AFIO 时钟读取 MAPR，发现冲突则恢复原时钟门状态，不修改 MAPR 或调试配置。波特率或时钟无法支持时返回 HAL_ERROR。

成功后的相同波特率重复调用返回 HAL_OK，不重置数据；不同波特率重复调用返回 HAL_BUSY，不新增重新配置接口。

GPIO 引脚也必须由调用者预留给驱动。占用检查不能识别原工程所有未来的初始化计划，因此原工程不得在 RC_Init() 成功之后再初始化 USART1、TIM4 或 PA9/PA10。

## 避免生成文件冲突

不导出 USART1_IRQHandler、TIM4_IRQHandler、huart1、htim4 或 MSP 回调等生成器常用符号。已有 uart.c、tim.c、stm32xx_it.c 可以继续编译。

初始化时复制当前中断向量表，保留其他中断与异常入口，仅替换 USART1、TIM4 两项，切换 VTOR 到驱动私有、正确对齐的 RAM 表。F103 表内容占 236 字节；H723 表内容占 716 字节，另有链接对齐开销。H723 开启数据缓存时处理向量表的缓存可见性。

使用标准 CMSIS NVIC 接口，保留其他中断的优先级及状态。驱动接入后，工程不得再次迁移或覆盖向量表。标准 CubeIDE/GCC 工程无需为此新增链接脚本段；自定义启动、向量表或 RTOS 移交流程需单独核验。

文件共存不等于同一硬件外设可供两个模块同时使用。若 main() 已调用 MX_USART1_UART_Init() 或 MX_TIM4_Init()，驱动会返回 HAL_BUSY；要使用遥控驱动，应避免调用这两个初始化函数，保留其他生成内容。

## 验证与交付

1. 运行现有两套 C 协议测试，确认帧解析、序号、使能和超时行为保持一致。
2. 用官方 F1/H7 CMSIS 与 HAL 头文件交叉编译，不开启 HAL UART/TIM 模块。
3. 与包含同名生成中断函数的工程桩进行链接，验证无重复定义，并检查没有 UART/TIM HAL 函数依赖。
4. 验证占用返回不修改外设或 g_rc、向量保留、重复初始化行为以及参数错误的失败路径。
5. 更新两套 .c/.h、接入说明与可下载压缩包。Android App 与通信协议不改动。

编译、链接和模拟测试不代表实机通信验证；F103/H723 实机的接收、定时及断连行为需烧录后确认，本次不自动烧录硬件。
