# Remote Control v2 协议

BT630 通过 BLE FFF2 写入，经 UART 透传给 STM32；App v1.6.0 只保留 BT630 连接。
固定 20 字节、所有多字节数字小端序，不传 C 结构体内存布局。

| 字节 | 类型 | 内容 |
| --- | --- | --- |
| 0–1 | uint8[2] | A5 5A |
| 2 | uint8 | 版本 02 |
| 3 | uint8 | 序号，每次发送加一，255 后回到 0 |
| 4–5 | int16 LE | 左 X，−1000～1000 |
| 6–7 | int16 LE | 左 Y，−1000～1000 |
| 8–9 | int16 LE | 右 X，−1000～1000 |
| 10–11 | int16 LE | 右 Y，−1000～1000 |
| 12–16 | 40 bits LE | 四个滑块，每通道 10 bits，0～1000 |
| 17 | uint8 | bit0 使能，bit1 急停，bit2–7 必须为 0 |
| 18–19 | uint16 LE | CRC16 |

滑块打包值为 `slider1 | (slider2 << 10) | (slider3 << 20) | (slider4 << 30)`，以五个字节低位优先发送；每个字段的 1001～1023 均非法。v2 无保留字节。

接收驱动同时接受旧版 v1：字节 12～13、14～15 分别为两个 uint16 LE 滑块，字节 16 为标志，字节 17 必须为零。v1 帧发布时将 `sliders[2]`、`sliders[3]` 清零。两版本共用序号基线和超时，允许混合接收。新版 App 默认发送 v2，必须配套更新驱动；旧驱动无法接收 v2。

向右为 X 正，向上为 Y 正。方形摇杆每个轴独立限幅，允许 X=1000、Y=1000。
App v1.2.0 可将每个摇杆的最大绝对值设为 1～1000：例如设为 255，线上轴数值实际范围为 −255～255，接收驱动不再缩放。自由模式独立应用 X/Y 死区；仅横向 Y 恒为 0，仅纵向 X 恒为 0。帧格式和接收限幅仍保持本协议。
App v1.3.0 滑块默认发送分档实际值 0、1、2；支持 2～8 个自定义档位（每档 0～1000）或连续 0～1000。STM32 的 `sliders[]` 直接保存该整数，v2 的四通道保存在 `sliders[0..3]`，无需接收端缩放。
未使能或急停时，四轴和四个滑块必须全部为零；非法组合整帧拒绝。
急停优先于使能。发送端会把同时出现的使能与急停转成只保留急停。

CRC-16/CCITT-FALSE：多项式 `0x1021`，初始 `0xFFFF`，输入/输出不反射，结果不异或。
仅覆盖字节 2～17，CRC 值低字节先发送。标准检验字符串 `123456789` 得 `0x29B1`。

示例：版本2，序号255，左(-1000,+1000)，右(-1,0)，滑块(0,1000,1,999)，已使能：

```text
A5 5A 02 FF 18 FC E8 03 FF FF 00 00 00 A0 1F C0 F9 01 7B CE
```

CRC 为 `0xCE7B`，已用 Python `binascii.crc_hqx(payload, 0xFFFF)` 独立核对，并用于 Android 和 C 测试。接收方按字节处理，不能假设 UART 回调一次对应一帧。
帧头、版本、保留位、CRC、范围校验完成后才发布控制量；坏帧不能刷新超时。

序号差按 uint8 计算：1～127 为新帧，0 为重复，128～255 为旧帧，不接受也不刷新超时。
300 ms 未收到新有效帧后禁用、归零并置停止。驱动 v2.3.0 起，初始化、手动重置、MCU 重启或超时后，首个通过全部帧校验的帧重新建立序号基线，允许使能帧直接恢复输出，不要求先收到禁用帧。建立基线后的重复或过旧序号仍被拒绝。

因此手机仍保持使能时，短暂停发后恢复或 MCU 重启后均可能自动恢复控制。超时后的首帧不与旧基线比较序号；序号机制不提供无线身份认证或精确消息年龄证明。App 自身断开、未开启后台保持时切后台、或实际重连时仍会关闭使能，需手动开启。

TIM4（F103）或TIM5（H723）用作 1 ms 时间基准。App 默认进入后台关闭蓝牙；开启后台保持时继续发送当前使能和控制值。通信实际中断时，MCU 端超时归零；
不会承诺通过不可靠链路瞬时送达急停。v1/v2 不含 ACK 或 STM32 回传遥测。
