# Remote Control v1 协议

HC-05（SPP 字节流）和 BT630（BLE FFF2 写入，经 UART 透传）使用同一帧。
固定 20 字节、所有多字节数字小端序，不传 C 结构体内存布局。

| 字节 | 类型 | 内容 |
| --- | --- | --- |
| 0–1 | uint8[2] | A5 5A |
| 2 | uint8 | 版本 01 |
| 3 | uint8 | 序号，每次发送加一，255 后回到 0 |
| 4–5 | int16 LE | 左 X，−1000～1000 |
| 6–7 | int16 LE | 左 Y，−1000～1000 |
| 8–9 | int16 LE | 右 X，−1000～1000 |
| 10–11 | int16 LE | 右 Y，−1000～1000 |
| 12–13 | uint16 LE | 滑块 1，0～1000 |
| 14–15 | uint16 LE | 滑块 2，0～1000 |
| 16 | uint8 | bit0 使能，bit1 急停，bit2–7 必须为 0 |
| 17 | uint8 | 保留，必须为 0 |
| 18–19 | uint16 LE | CRC16 |

向右为 X 正，向上为 Y 正。方形摇杆每个轴独立限幅，允许 X=1000、Y=1000。
App v1.2.0 可将每个摇杆的最大绝对值设为 1～1000：例如设为 255，线上轴数值实际范围为 −255～255，接收驱动不再缩放。自由模式独立应用 X/Y 死区；仅横向 Y 恒为 0，仅纵向 X 恒为 0。帧格式和接收限幅仍保持本协议。
未使能或急停时，四轴和两个滑块必须全部为零；非法组合整帧拒绝。
急停优先于使能。发送端会把同时出现的使能与急停转成只保留急停。

CRC-16/CCITT-FALSE：多项式 `0x1021`，初始 `0xFFFF`，输入/输出不反射，结果不异或。
仅覆盖字节 2～17，CRC 值低字节先发送。标准检验字符串 `123456789` 得 `0x29B1`。

示例：版本1，序号255，左(-1000,+1000)，右(-1,0)，滑块(0,1000)，已使能：

```text
A5 5A 01 FF 18 FC E8 03 FF FF 00 00 00 00 E8 03 01 00 DC 37
```

CRC 为 `0x37DC`，已用独立 CRC 算法核对。接收方按字节处理，不能假设 UART 回调一次对应一帧。
帧头、版本、保留位、CRC、范围校验完成后才发布控制量；坏帧不能刷新超时。

序号差按 uint8 计算：1～127 为新帧，0 为重复，128～255 为旧帧，不接受也不刷新超时。
300 ms 未收到新有效帧后禁用并归零；此后先接收一个有效禁用帧重新建立序号基线，
再接受新序号的使能帧。该机制用于排除常见的重复/过期帧，不提供无线身份认证或精确消息年龄证明。

初始化或 MCU 重启后也需要先收到全零禁用帧建立基线，再接受新序号的启用帧。
如果手机在 MCU 重启时仍保持使能，请先关闭使能再重新开启。

TIM4 用作 1 ms 时间基准。App 进入后台立即关闭蓝牙，停车的最后保障是 MCU 端的超时；
不会承诺通过不可靠链路瞬时送达急停。v1 不含 ACK 或 STM32 回传遥测。
